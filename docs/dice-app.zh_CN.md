# passport-pocket-dice v0.2

本应用以深蓝与琥珀色竖屏界面替代硬件测试菜单，离线运行并复用 Passport BSP。
Flipper Zero 的 [DnD Dice](https://github.com/Ka3u6y6a/flipper-zero-dice)
仅作为功能参考，没有引入其 GPL 源码、图像或界面。

## 功能与操作

- 硬币、D4、D6、D8、D10、D12、D20、D100、D200；骰子结果包含 1 和 N 两端。
- 每次投掷 1–6 颗骰子，720 毫秒动画，显示每颗点数及总和。
  D4 和 D6 使用圆点骰面；硬币固定一枚，显示正面或反面。
  单颗骰子和硬币在原动画行水平居中，多颗仍沿用三列网格。
  标题及历史描述使用 `1粒 点数4 骰子`、`2粒 点数6 骰子` 等格式。
- 最近 12 次投掷，最新在前，保留每颗点数和最高 1200 的总和。
- 右上角显示电量；读数不可用时显示 `--%`。

| 页面 | 上 / 下短按 | 确定短按 | 长按确定 | 长按下键 |
| --- | --- | --- | --- | --- |
| 投掷 | 上一种 / 下一种，循环切换 | 再投一次 | 数量设置 | 历史记录 |
| 数量 | 增加 / 减少，限制在 1–6 | 返回 | 返回 | 无操作 |
| 历史 | 更新 / 更旧，到边界停止 | 返回 | 返回 | 无操作 |

长按沿用 BSP 的 500 毫秒阈值。上下双击相当于两步，确定双击最多投掷一次。
动画期间忽略操作。硬币数量固定为一，切换到硬币会将数量重置为一。
页脚第二行改为 `长按确定改数量 下键查记录`。
按键行为不变，查看历史仍需长按下键。

闲置 30 秒调暗背光，90 秒熄屏，5 分钟进入深睡。熄屏后的第一次按键仅亮屏；
任一功能键可唤醒深睡，松开唤醒键后再操作。应用通过 RTC 内存保留深睡前
的本次会话，但关机、复位或刷机会丢失。没有 NVS 写入和网络、音频服务。

## 实现与边界

`main/dice_model.c` 是独立状态机；`main/dice_ui.c` 使用普通 LVGL 控件创建全新页面，
未链接 demo 测试页和 `ui_pixel` 界面。`main/main.c` 将按键事件入队并独占模型。
该任务的所有 UI 操作均持 BSP LVGL 锁；电池 I2C 读取及外设关闭在锁外执行。
页面切换时没有定时器或异步生产者持有已删除子控件。

随机字来自 `esp_random()`，拒绝采样消除取模偏差，重试次数有界；
失败保留上次有效结果和历史。无线关闭时，ESP-IDF 不保证持续的真熵源。
本应用用于日常游戏，不是认证博彩或密码学随机数工具。
不启用会与 BSP 按键 ADC 冲突的额外 ADC 熵源。

保持默认 8 MB 分区表和 BSP 不变。启动后初始化并暂停音频芯片，不启动 Wi-Fi
和蓝牙。深睡复用 BSP 的按键引脚交回、电量计及音频暂停、共享总线和屏幕关闭。
关闭失败记录日志；终端交回失败通过重启恢复。真实功耗和唤醒行为需要实测。

中文使用 Noto Sans SC 的 16 像素、4 bpp 子集，行高 20 像素。
覆盖应用所有固定文字和可打印 ASCII，不支持任意外部文本。
字体来源和重建步骤见[资源说明](../assets/README.zh_CN.md#字库fonts)。
启动通过 `lv_font_get_glyph_dsc()` 逐字验证，拒绝占位符。
大数字使用 Montserrat 48，单颗数字使用 Montserrat 20。
LVGL 内存池为 32 KiB，应用任务栈为 6 KiB。

## 构建与验证

使用 ESP-IDF 5.5.3 和锁定的组件：

```sh
./tools/validate.sh --static
./tools/validate.sh --firmware
./tools/validate.sh
```

门禁包含确定性采样及边界、计时、历史滚动、失败原子性、亮度阈值、
字体字符清单与位图逐像素读回。均匀映射测试不代表测量物理随机源熵。

Managed Components 下载完成后，可使用真正的固定版本 LVGL 与应用源码运行
无窗口渲染：

```sh
cmake -S tests/dice_ui -B build/ui-test -DCMAKE_BUILD_TYPE=Debug
cmake --build build/ui-test
cd build/ui-test
./dice_ui_test
```

验证字形查找、文字边界、900 次页面切换和 LVGL 堆完整性，输出 PPM 页面截图。
这是软件渲染结果，不是真机照片或物理显示验证。Windows 可显式选择 Ninja
及本机 GCC。仓库 shell 门禁需要 Git Bash、指向已激活 Python 的 `python3`、
主机 C 编译器及 Windows actionlint。
Windows 的 ESP-IDF 会拒绝 MSYS 环境。如果完整 shell 门禁因此中止，
固件阶段改用原生 ESP-IDF PowerShell：新建构建目录，从受版本控制的默认配置
生成隔离的 SDKCONFIG，再用相同的仓库工具合并、验证及归档。
应将 shell 门禁的环境限制与原生构建、主机测试结果分别报告。

验证后的 `build/passport-pocket-dice-full.bin` 是从 **0x0** 刷写的合并固件。
对应 ELF/MAP 和清单保存在 `build/firmware/<sha256>/`。
不能将仅应用程序的二进制刷到 0x0。合并刷写可能重置 NVS/PHY 数据，
无需整片擦除。必须针对本次确切固件获得明确确认后才刷机。

## 仍需真机验收

1. 检查启动、所有中文及标点、裁切、颜色、D4/D6 圆点和单颗骰子/硬币居中。
2. 检查全部九种类型、数量边界、连按和长按、动画期间忽略输入、
   历史边界，以及六颗 D200 的结果。
3. 检查电量正常和失败状态、30/90 秒背光行为、5 分钟深睡，
   确认唤醒不产生意外投掷。
4. 确认深睡保留会话、冷启动清除会话。
5. 观察空闲堆及最大连续块、长期稳定性、温度和闲置电流。

构建、主机测试和设备测试分别报告。构建流程不包含刷机、提交、推送或发布。
